# NetDisk 前端

独立的简体中文 Material 风格网盘界面，使用原生 JavaScript + Vite，无 UI 框架运行时依赖。不修改 Rust、数据库或 Cargo 配置。

## 启动

需要 Node.js 22.12+（或 20.19+）。在项目根目录执行：

```bash
cd frontend
npm install
npm run dev
```

访问 http://localhost:5173。未登录时显示登录 / 注册入口，登录后加载后端文件。需要启动后端才能使用文件功能。

```bash
npm run build
npm run preview
```

生产文件输出到 `frontend/dist/`。`preview` 仅预览构建文件；连接后端请使用开发服务器，或配置生产反向代理。

## 界面与交互

- 文件列表 / 网格、类型分类、全局名称搜索、修改时间 / 名称 / 大小排序。
- 文件夹导航、面包屑、新建文件夹、重命名、批量选择。
- 星标与视图偏好保存在当前浏览器；星标没有调用后端接口。
- 文件上传、拖放上传、上传进度、成功与错误提示。
- 登录后可从文件菜单或详情弹窗下载真实文件，保留原文件名；文件夹菜单提供「下载 ZIP」，保存为「文件夹名.zip」。
- 分享弹窗支持单文件、文件夹与批量分享，可设置 1 天、7 天、30 天、自定义或永久有效期，创建后复制六位分享码与链接。
- 「我的分享」从后端加载当前账户创建的分享，支持搜索、查看有效期、复制链接、查看与撤销；切换浏览器也能管理。
- 独立提取页 `/#/share` 支持输入分享码；链接 `/#/share/012345` 可直接打开，登录后提取，文件夹下载为 ZIP。
- 账户弹窗支持登录、注册、退出；登录令牌仅存于 `sessionStorage`。
- 管理员专用「用户管理」：查看全部账户，修改用户名、重置密码和角色，进入任意用户空间管理文件；输入用户名确认后可永久删除用户及其文件，当前登录账号不可删除。当前管理对象在顶部明确显示，上传和新建文件夹归属该用户。
- 响应式移动布局、键盘焦点、弹窗 Escape 关闭、`/` 搜索快捷键。

页面仅显示后端真实文件，不提供示例数据或本地模拟操作。退出登录后清空文件列表并返回登录入口；已有令牌会在打开页面时验证，失效后返回登录入口。文件内容预览、回收站与恢复功能尚未接入。

## 后端连接

1. 按原有方式启动 Rust 后端（默认端口 3000）。
2. 启动前端开发服务器，点击「登录」或「注册账户」。
3. 前端向同源 `/api` 请求，Vite 将其转发到 `http://127.0.0.1:3000` 并去掉 `/api` 前缀，无须改后端 CORS。
4. 自定义后端地址时，将 `.env.example` 复制为 `.env.local`，修改 `VITE_API_TARGET`，重启 Vite。

所有请求集中在 `src/api.js`，直接对应当前 `src/api.rs`：

| 功能 | 接口 | 状态 |
| --- | --- | --- |
| 登录 | `POST /login` | 按纯文本 JWT 解析 |
| 注册 | `POST /register` | 已接入 |
| 当前用户 | `GET /user_info` | 已接入，包含 `is_admin` |
| 用户管理 | `GET /admin/users`、`GET/PATCH/DELETE /admin/users/:id` | 仅管理员，支持用户名、密码和角色修改，以及永久删除用户 |
| 文件列表 | `GET /files?user_id=...&parent_id=...` | 返回指定父文件夹的直接子项；`parent_id` 未传或为空时使用根目录 |
| 文件元数据 | `GET /files/:id` | 适配方法已预留 |
| 新建文件夹 | `POST /files` | 已接入 `is_directory: true`，空哈希 |
| 重命名 | `PATCH /files/:id` | 已接入 |
| 永久删除 | `DELETE /files/:id` | 已接入；有不可撤销确认弹窗 |
| 上传 | `POST /upload?parent_id=...` | multipart，字段名 `file`；`parent_id` 未传或为空时使用根目录，多文件逐个上传 |
| 下载内容 | `GET /download/:id` | 已接入；携带 JWT，以 Blob 接收文件或文件夹 ZIP |
| 分享列表 | `GET /share_records` | 从服务器读取；管理员支持指定用户或全部分享 |
| 撤销分享 | `DELETE /share_records/:share_id` | 创建者或管理员，撤销后链接失效、原文件保留 |
| 创建分享 | `POST /create_share` | 发送 `file_id_list` 和 `expired_at`（Unix 秒 / null），接收六位 `share_code` |
| 提取分享 | `GET /shares/:code` | 接收文件元数据数组，目前需要 JWT |
| 分享下载 | `GET /shares/:code/download/:id` | 携带 JWT，通过分享下载接口获取 Blob，文件夹保存为 ZIP |
| 回收站、恢复、配额 | 待定义 | `api.js` 中留有独立占位方法 |

受保护的请求使用 `Authorization: Bearer <token>`。请求错误会显示于界面，登录失败不会退回虚假的成功状态。

下载通过同源 `/api/download/:id` 代理访问后端，使用文件元数据中的名称触发浏览器保存，支持中文文件名；401、404 等失败响应不会保存为文件。当前实现先完整接收 Blob 再触发保存，大文件会占用相应浏览器内存。同一文件正在接收时不会重复请求。

上传时传入当前文件夹的 `parent_id`，文件保存到该文件夹；非根目录必须存在、为目录且属于当前用户。真实 DELETE 永久删除，前端不会将其伪装成可恢复的回收站操作。实际可用性依赖后端实现与运行配置。

进入文件夹、返回根目录及刷新时重新请求该目录列表。真实空间「我的文件」搜索限于当前目录；星标、最近使用及分类页逐级加载目录后筛选。

首页「最近修改」与侧栏「最近使用」目前按 `file_updated_at` 展示最近修改的文件；后端增加访问记录后，可替换该数据来源。真实空间只显示文件总大小，容量配额留待后端定义。

## 分享说明

分享列表通过 `/share_records` 读取，撤销通过 `DELETE /share_records/:share_id` 完成，不再使用浏览器本地分享记录。撤销需要确认，原文件保留；读取和撤销失败会显示错误。管理员可在用户管理中查看指定用户分享或全部分享，普通用户只能管理自己创建的分享。分享密码尚未实现。分享提取页只从 `/shares/:code` 读取文件，下载只调用分享下载接口，不调用所有者下载接口。分享文件夹目前支持整包下载，不支持浏览目录内的文件。

分享链接采用 URL hash，静态部署不需要为分享路径增加回退规则。打开链接后会保留分享码，未登录时提示登录，登录成功后自动加载。同一分享文件的重复下载会被阻止，读取失败提供重试，下载失败不会保存错误响应。复制需要浏览器剪贴板权限；不可用时提供选中内容手动复制。

## 生产部署

将 `dist/` 托管为静态文件，并将同源 `/api/*` 反向代理到 Rust 后端，转发时移除 `/api`。例如 `/api/files` 应转发为后端 `/files`。Vite 的代理仅在开发时生效，不需要将页面文件塞进 Rust 项目。

## 主要文件

- `src/main.js`：页面、状态与交互。
- `src/style.css`：Material 风格组件与响应式布局。
- `src/shares.js`：创建分享、浏览器分享记录、提取路由和分享下载。
- `src/api.js`：后端接口与未实现功能占位。
- `src/icons.js`：内联 SVG 图标，无外部字体或图片请求。
- `vite.config.js`：开发端口和 API 代理。
